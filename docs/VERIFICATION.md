# Проверки, выполненные 30 октября 2026

**Русский** · [English](VERIFICATION.en.md)

Среда: Ubuntu/WSL2, Linux x86_64, Python 3.14.4 в .venv; контейнерный Python 3.14,
PostgreSQL 18.6, RabbitMQ 4, OpenTelemetry Collector 0.164.0, Docker 29.1.3,
Compose 2.40.3. На WSL доступно около 7.5 GiB RAM; параллельно работают другие
локальные приложения. Образы и зависимости закреплены в исходниках.

## Автоматические проверки

- **42 теста EventHub:** строгие JSON/схемы/подписи; конкурентная дедупликация и
  конфликты; проект/роль/source/отзыв/срок ключа; CSRF/сессии/заголовки; экспорт,
  capture, метрики; retention и запрет retry удалённого тела; разные ручные run
  и сохранение истории; реальные PostgreSQL/RabbitMQ/HTTP, аренды и восстановление.
- Hypothesis выполняет 25 сгенерированных последовательностей через настоящий
  HTTP receiver B: перестановки/повторы/пропуски сохраняют максимальную полученную
  версию и не создают повторного эффекта одного event ID.
- `pip check`, Ruff lint/format и проверка исходников на приватные ключи.
- **143 проверки Django-сайта** после миграции адаптера: прошли, один live-тест
  штатно пропущен без его временного ключа. Отдельно **все 7 тестов источника**
  выполнены с live-ключом, включая HTTP-передачу трёх снимков из тестовой базы.
  Ключ отозван. Это не публикация новой версии старого GitHub-репозитория.

## Семь окон сбоя

| Окно | Полученное свидетельство |
| --- | --- |
| Event/Outbox commit → публикация | Реально остановлен основной broker; API дал 202; после старта две доставки accepted |
| Broker confirm → отметка outbox | Исключение после реального publisher confirm; повторная публикация, один исходный delivery |
| Claim → HTTP | Истёкшая аренда восстанавливается scheduler; новое задание обрабатывается |
| Receiver commit → ответ | Реальный commit+задержка HTTP, реальный timeout и повтор; B не дублирует эффект |
| Worker commit → ack | Реально закрыт AMQP channel с unacked сообщением; redelivery не создаёт новую попытку |
| Lease expired → поздний результат | Старый token отвергается до и после завершения нового владельца |
| Receiver replay step → checkpoint runner | Управляемое прерывание после commit; восстановление через invocation ledger; тот же normalized hash |

Исключения в управляемых точках моделируют остановку процесса; они не выданы за
физическое выключение компьютера. RabbitMQ outage, HTTP timeout, channel loss и
базы при этом настоящие. Произвольные kernel/network-катастрофы не проверялись.

## Контейнеры, данные и браузер

- Полный основной Compose-стенд запущен; API опубликован только на 127.0.0.1:8100.
- Независимый `eventhub-freshcheck`: пустые тома, init ролей/баз, Alembic, bootstrap,
  оба HTTP replay с expectations_met=true. Временный стенд и его тома затем удалены.
- Оба receiver не могут открыть внешний TCP 1.1.1.1:443, подключиться к core DB
  своими ролями; основных секретов и docker.sock в контейнерах нет.
- Три custom-format backup восстановлены в новые случайные базы; pg_restore
  завершился успешно, количества строк всех 25 таблиц совпали; временные базы удалены.
- OpenTelemetry Collector действительно получил spans API/доставки/replay.
- Chrome/Playwright: 4 раздела × 3 ширины (1440, 768, 375), отсутствие JS-ошибок
  и горизонтального переполнения; создание сценария из события и запуск через UI,
  открытие отчёта и закрытие Escape. Скриншоты
  сняты с работающего приложения, не являются макетами.

## Небольшое измерение нагрузки

50 синтетических событий, 5 параллельных HTTP-запросов, локальный Docker/WSL:

| Показатель | Наблюдение |
| --- | --- |
| Принято | 50 из 50, HTTP 202 |
| Время группы | 2.237 s |
| Медиана ответа API | 201.34 ms |
| p95 ответа API | 316.12 ms |

Это время **приёма API**, не latency прикладного эффекта. Во время измерения
использовался основной локальный стенд с worker/Collector и другие приложения;
нет выделенного hardware или серии производственных испытаний. Числа не являются
SLA, пределом пропускной способности или сравнением фреймворков. Сумма текущей
памяти десяти контейнеров после эксперимента около 0.8 GiB; это разовый снимок.

## Воспроизведение и приватность

Команды перечислены в README и docs/OPERATIONS.md. Полные JSON/логи находятся
в `.local/reports`: check-release.log, booking-source-live.log, isolation.json,
broker-recovery.json, restore-drill.json, fresh-start.json, load-probe.json,
браузерные отчёты и replay reports. Файлы с ключами/дампами не публикуются.
В исходниках только обезличенные сценарии и фотографии интерфейса без ключей.

GitHub Actions workflow подготовлен по официальным
[checkout](https://github.com/actions/checkout) и
[setup-python](https://github.com/actions/setup-python), с закреплёнными commit SHA.
Статус hosted CI доступен в [GitHub Actions](https://github.com/Sasambatra/eventhub-replaylab/actions/workflows/check.yml).
Результат конкретного hosted run оценивается по его commit SHA; локальные
проверки выше не подменяют его. Публичный сервер не развёрнут.
