# Источник: Django Salon Booking

Адаптер предназначен для [Django Salon Booking](https://github.com/Sasambatra/django-salon-booking).
В исходной локальной рабочей копии он установлен и проверен. Его окружение и существующие секреты не менялись.
Миграция `0006_booking_event_revision_eventhuboutbox` применена. По умолчанию
отправка выключена. Существующие записи клиентов автоматически не экспортируются.

`booking-source.patch` содержит изменения адаптера и тесты относительно
публичного коммита `34b5d1baf92d8165acdcfed0c4555b110217b80a` сайта. Для другой
копии исходного проекта сначала выполните `git apply --check` и проверьте изменения;
не накладывайте патч повторно на уже изменённую рабочую копию. Это адаптер
конкретного Django-приложения, универсальный SDK не требуется.

## Как устроено

Каждое изменение бронирования сохраняет положительный номер версии. При включённой
интеграции в той же транзакции создаётся EventHubOutbox: отдельная строка с готовым
неизменяемым снимком. Если запись бронирования откатится, событие тоже откатится.
Обрабатываются резервирование, успешная/неуспешная демооплата, отмена и истечение
срока. Повтор одной операции не создаёт нового изменения.

В событии только UUID бронирования, версия, статус и служебный CloudEvents-конверт.
Нет имени, телефона, email, стоимости или ключей. Независимая команда отправляет
уже зафиксированные строки без удержания блокировки базы на время сети. После
неизвестного результата повторяет исходный UUID/содержимое. 409 останавливает
отправку; временные ошибки ограничены 12 попытками. Просроченный работник не может
перезаписать результат нового владельца аренды. Telegram работает отдельно.

## Включение для своего локального сайта

1. Создайте ключ через `POST /v1/keys` от владельца EventHub: role `source`,
   scopes `["events:write"]`, sources `["urn:studio:booking"]`. Ответ показывает
   ключ один раз; сохраните его в приватной `.env` сайта, без публикации и чата.
2. В `.env` сайта задайте `EVENTHUB_ENABLED=true`,
   `EVENTHUB_URL=http://127.0.0.1:8100`, `EVENTHUB_SOURCE=urn:studio:booking`,
   `EVENTHUB_API_KEY=<полученный ключ>`. Перезапустите Django, чтобы он прочитал настройки.
3. В папке сайта загрузите свою `.env` и выполните
   `.venv/bin/python manage.py publish_eventhub --once`. Без `--once` команда
   опрашивает журнал каждые две секунды; останавливается Ctrl+C. Сервер сайта и
   отправитель должны получать одинаковые настройки.

Рабочая папка этих команд — корень копии Django Salon Booking. `manage.py`
запускает Django, `publish_eventhub` — новый отправитель, `--once` — один проход.
Обычный просмотр сайта не отправляет события. Команда отправляет только новые
снимки, накопленные при включённой интеграции. HTTPS обязателен для нелокальных
адресов; перенаправления и системные HTTP-прокси выключены.

## Что проверено

Семь тестов источника: откат транзакции, версии/минимизация данных, повторная
отправка, постоянная ошибка, истечение срока, выключенная интеграция и настоящий
HTTP-проход. Последний использовал временную тестовую базу Django и ограниченный
ключ с source `urn:studio:booking-test`; три тестовых снимка приняты EventHub.
Тестовый ключ затем отозван. Реальные записи клиентов не использовались.
